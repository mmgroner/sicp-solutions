## Why? 

When defining `x`, only the first item of the stream is evaluated, which calls `proc` and prints 
```

0
```
aka `(newline) (display 0)`.

Then, calling `(stream-ref x 5)` calls `stream-cdr` on the stream successively until 5, however, the `car` of the stream was already evaluated, and we memoized the result, hence, no double zeroes. Once `stream-ref` reaches 5, it returns 5 and prints it to the console, thus `55`. After retrning the evaluation, the repl automatically starts a new line, and evauates the next expression.

At this point, we call `(stream-ref x 7)`. The interpreter has already memoixed values 0 - 5, so `show` is not called on those elements. When the interpreter reaches 6, the value has not yet been evaluated, so we call `show` on 6, which prints out:

```

6
```
again, `(newline) (display 6)`. Then comes 7. At that point, the call to `stream-ref` returns 7, which is output to the console as well, along with a newline, and the program ends.
